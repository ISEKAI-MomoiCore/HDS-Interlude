# 文风拟真度大型测试设计（Round 1）

日期：2026-11-22。基于 1.0.1-rc61 工作区。只测私聊主链。
方法学前作：[连续生活写作实验（2026-09-11）](2026-09-11-lived-writing.md)、[用户原文版](2026-09-11-user-authored-writing.md)、`test/model-behavior.test.ts`（生产提示词合同测试骨架）。

## 0. 目的与待答问题

用真实模型 API 回答四个问题：

1. **不同写作提示词（文风 / 人称 / 剧本注重点 / 叙述语言）在不同对话场景下，对拟真度的影响方向是什么？**
2. **多轮长上下文剧本下，哪种文风的细节表现最优异？**（长线记忆承接、细节后果化、跨日一致性）
3. **哪种情绪表达更真实？**（情绪通过动作/细节流露 vs 直接命名；情绪比例感；冲突下的反应）
4. **提示词需要什么限度的自由？**（约束过严 → 模板化；过松 → 合约漂移。找到拟真度与合约稳定性的最优档位）

明确**不在**本次范围：群聊意愿门、QQ 空间、考据、主动联系闭环、投递管线行为。这些留待 Round 2。

## 1. 总体设计

- **载体**：轻量合成 harness（用户已选定）。复用生产 `systemPrompt()` 构建链（同 `test/model-behavior.test.ts` 的做法），harness 自持 payload 累积器按八段式 schema 组包，直调 API，逐轮累积 `recentScript` 形成长上下文。
- **评估**：双审查制（用户已选定）。
  - **一审（agent gate）**：只评两件事——①动作决策是否明显不合理（回复/沉默/已读不回的选择是否合乎场景）；②即将实际发出的回复语句是否显得正常。**不评审剧本 prose**。gate 是保守过滤器：只拦"明显不过关"，拿不准的放行并标记。
  - **二审（人工，用户）**：阅读 gate 放行的运行段，按锚定量表为文风执行度与拟真维度打分，标记"出戏点"。
- **规模**：先小后加，文风轴采用**两段式筛选**（sprint 粗筛 → 复跑精评）。Round 1 全程 **41 个运行段（折合 24 轮等效段约 27 个）、约 674 个模型回合**；每阶段末有决策点，可随时收敛。
- **变量控制**：同一模型、同一采样参数、同一场景脚本（用户消息与模拟时钟逐轮一致）；每个运行段只允许一个轴变化。人物轴（§3.5）引入后，"同一 fixture"限定为**人物内**：同一人物内各臂输入逐字一致，跨人物的场景职业锚点由 perPersona 变体承载（人物内臂间单变量纪律不破）。

## 3. 变量设计（四个轴）

提示词组装规则（所有运行段统一）：`生产 systemPrompt(...) + 文风段(A) + 人称段(P) + 注重段(F) + 自由度段(D)`，各段独立拼接、互不覆写，拼接顺序固定并记录哈希。改动只发生在用户可配置字段（mainPrompt / stylePrompt / 故事文风），不触碰固定合约区。

### 3.1 A 轴：文风（四个家族 + 作者在场度光谱）

A 轴按"作者在场度"（作者腔压过生活本身的强度）组织为 0-3 光谱。核心假设：**拟真度随在场度上升而下降，但曲线形状未知**——1-2 档可能出现反直觉点（强风格天然抑制 AI 默认腔，拟真不降反升）。本测试的产出之一就是这条曲线。

| 在场度 | 臂 |
| --- | --- |
| 0 不可见 | A0、A1、E0 |
| 1 可感不抢戏 | A2、A3、W1、W2、W6、W7、W10、E1、E2 |
| 2 明显作者腔 | W3、W4、W5、W8、W9、N1、N2 |
| 3 结构性改写 | N3、N4、X1、X2（合约压力级，见下） |

> A-E 臂额外带一个独立维度：**叙述语言**（中文/英文）。在场度与语言维度正交，E0 在场度=0 专门隔离语言变量。

#### A-E 家族：剧本语言变量（英文叙述 + 中文回复）

**机制可行性**：transport mirror 合约要求 reply.content 与 `<say>` 内容逐字一致，但并不要求 prose 与 say 同语言。A-E 臂的合约内实现 = 剧本 prose 用英文写，`<say>` 标签内嵌她的中文原话，中文原话逐字镜像到 reply.content——即"翻译小说"质感：中文世界、中文对话、英文叙述层。角色设定与用户消息保持中文不变（她仍是个说中文的中国人，变的只是叙述语言）。

| 臂 | 代号 | 语言段草案（实际提示词用英文） |
| --- | --- | --- |
| 英文基线 | E0 | Write the script prose (narration) in English. The protagonist's actual spoken words — inside `<say>` tags and mirrored in reply.content — must be natural colloquial Chinese, the way a Chinese person actually texts. Never mix English into the spoken bubbles (proper nouns excepted). Structured field values follow the prose language; quotes must be exact substrings of the English prose. All timing, evidence and transport rules of the fixed contract are unchanged. （隔离"叙述语言"这个单变量：风格=基线） |
| 卡佛·英 | E1 | E0 语言规则 + W7 卡佛风格（以英文原文写就，不做中译转述——卡佛的声腔在英文里最完整） |
| 石黑一雄·英 | E2 | E0 语言规则 + W10 石黑一雄风格（英文原声；他的克制与留白在叙述语言里是母语级的） |

**A-E 臂的研究问题**：①叙述语言切换本身对拟真是净收益还是净干扰（E0 vs A0）；②西方作家的声腔在"母语叙述+中文气泡"下是否比"中译腔"更拟真（E1/E2 vs W7/W10）；③中译腔回归——英文句法是否渗进她的中文气泡；④双声部风险——英文内心与中文嘴是否像同一个人。

#### A-N 家族：叙事结构

| 臂 | 代号 | 结构段草案 |
| --- | --- | --- |
| 蒙太奇短句 | N1 | 剧本用蒙太奇式短句：一句一拍，画面跳接，不写过渡。像镜头切换一样在她的动作、环境细节、手机屏幕之间剪接。段落由碎句构成，每句自成画面。该发消息照发，时间线照走，只是叙述节奏被剪碎 |

### 3.5 P 轴：人物（多人物 fixture，2026-11-22 增补）

以"肥皂"人设模板（角色名/角色设定/视角/叙事文风/补充事实/相关人物/世界/主要地点）为格式参照，人物轴覆盖**性别 × 年龄 × 职业 × 性格 × 作息 × 表达习惯**的差异空间。全部人物共用同一聊天对象（阿澈，27 岁公司职员），使场景脚本的用户侧内容（加班/开会/见客户）对每个人物都成立。

字段映射：角色设定 → `character`；视角 → `perspective`；补充事实 → `supplementaryFacts`；相关人物 → `supportingCast`；世界/主要地点 → `world`/`location`。**模板"叙事文风"栏只记录不注入**（人物文件 `styleNote` 字段）——风格槽由 A 轴臂统一控制，否则人物文风与臂文风叠加会破坏单变量纪律；Round 2 的"真实配置复刻"模式再启用该栏。

**人物 × 场景的职业锚点**：S1/S3/S7/S10 中原为林晚定制的引用（赶demo、歌单、朋友小鹿的生日礼物）由 `perPersona` 变体按人物替换（肥皂→菜谱探店/希绘生日、江叙→下夜班的剧/同学小马、何川→减脂餐/妹妹等）。人物内各臂输入仍逐字一致；跨人物的场景文本差异属于人物包的一部分，不构成混淆变量。

**预算**：Phase 2P = 5 人物 × A0 × S-S sprint（5 段 × 12 轮 = 60 回合）。出围人物（sprint 评分最优 1-2 个）进 Round 2 的全场景复跑。

**破功的分类学**（A-N/A-X/W4 臂专用）：破功分两种，分别记账——
- **合约破功**：H1-H6 失败（JSON 结构坏、transport mirror 与 prose 不一致、时间越界、结构化字段丢失）。首要指标。
- **拟真破功**：合约完好但出戏（风格压过生活、独白替代行动、闪回混乱）。走正常拟真评分。
X/N 臂的研究问题是"哪种约束先破、以什么方式破"，这不只是失败，是架构边界的测绘。

### 3.2 P 轴：人称（剧本 prose 的人称；回复气泡永远是角色的直接话语，不受此影响）

| 臂 | 代号 | 人称段草案 |
| --- | --- | --- |
| 第三人称限知 | P0 | 基线（现行为）。以"她"为视点中心，只写她感知与知道的内容 |
| 第一人称 | P1 | 剧本以"我"叙述。视点纪律同 P0：只写"我"感知的；他人内心仍是不可见的猜想 |

### 3.3 F 轴：剧本注重点

| 臂 | 代号 | 注重段草案 |
| --- | --- | --- |
| 均衡 | F0 | 基线（现行为，不加额外指令） |

### 3.4 D 轴：自由度（提示词约束强度）

| 臂 | 代号 | 含义 |
| --- | --- | --- |

## 6. Harness 技术方案

### 6.1 文件布局（新建，不动现有源码）

```
test/realism/
  harness.ts          # 运行器：读矩阵定义→逐段逐轮执行→写 JSONL
  protocol.ts         # 请求适配（chat-completions 为主，预留 anthropic/gemini 分支）
  payload.ts          # payload 累积器（八段式子集，见 6.2）
  arms.ts             # 轴定义与提示词文本（本文档 §3 的落地，含 sha256）
  scenarios.ts        # S1-S10 脚本（消息、模拟时钟、advance 相位）
  checks.ts           # 硬校验（§7）与指标统计（§9）
  matrix.round1.json  # §5 矩阵
  out/<date>/<segment-id>/manifest.json + turns.jsonl + gate.jsonl
  report/             # 聚合指标、评审包（§8.3）
```

### 6.2 payload 累积器（与生产编译器的取舍）

直调 API 意味着绕过 `compileNarrativeContext`（service.ts 内部、依赖 DB 状态）。harness 自持累积器，**只实现私聊用户回合所需子集**，字段名与语义严格对齐 narrator 的 FIELD MAP：

- 每轮必发：`interval`（from/now/elapsedSeconds/nowLocal/nowLocalContext，由场景脚本驱动）、`currentEvent`（user-message-batch）、`recentScript`（累积轮出：protagonist-narrative / user-delivered-message / protagonist-delivered-message，带 ownership 标签与 occurredAtLocal）
- 按需：`currentParticipant`（displayName/unreadMessageCount）、`dueIntents`（S6 的 followUpCommitment 回路）、`workingDetails`（S7 的事实承接）、`authoringWindow.continuation`（续写书签）
- recentScript 窗口预算：实现"18 条锚点 ∪ 最近 5 分钟"投影规则（对齐 `contextEntryMode=fixed`），超出的旧条目按场景脚本折叠为 `previousScenes` 摘要——S7/S10 依赖此规则模拟真实长上下文
- **已知简化**（记入报告局限）：无压缩器、无长期事实检索、无 SceneFrame/lifeHandoff 校验、无时间导演。这些影响的是"管线行为"，不影响本轮"文风×场景"的写作质量主变量；但 S6 的 followUpCommitment 回路由 harness 手工按合约往返，须在实现时对照 `script/intent-lifecycle.ts` 的字段语义

### 6.3 回合执行与记录

1. 组 payload → `systemPrompt(phase='user-message', ...)`（或 advance 相位）→ API 调用（复用 model-behavior.test.ts 的重试/超时策略）
2. 解析 JSON → 跑硬校验（§7）→ 全量落 `turns.jsonl`（raw payload、raw response、parsed、hardChecks、派生指标）
3. 硬校验失败不中断段：记录后按"该轮她没有可见回复"继续（保持时间线推进），失败清单进报告

## 7. 硬校验清单（程序化预过滤，gate 之前）

复用并扩展 `model-behavior.test.ts` 的检查：

| # | 检查 | 判定 |
| --- | --- | --- |
| H1 | JSON 可解析；`script` 非空；`interaction` 存在；`seen` 为 boolean；`reply.mode ∈ {none,immediate,delayed}` | 失败 |
| H2 | immediate ⇒ content 非空；delayed ⇒ sendAt 为未来 ISO-8601；none ⇒ 无 content | 失败 |
| H3 | content 无 `<say` 泄漏、无 Markdown 围栏、无字段名泄漏（"lifeHandoff"等） | 失败 |
| H4 | `<sep/>` 只出现在 content 内部（不在首尾），分泡数 = 出现次数+1 ≤ 6 | 失败 |
| H5 | 无自造电话号码（`1[3-9]\d{9}` 且不在用户消息中）；无未知具名第三方发言（沿用 NARRATION_OR_KNOWN 白名单正则） | 失败 |
| H6 | script 无"手机震动/通知响起"类无证据入站事件（脚本未提供通知时） | 失败 |
| H7 | 跨轮重复：content 与本段此前任一轮完全相同；剧本开头 8-gram 重复率 > 60% | 标记 |
| H8 | 剧本时间越界粗检：script 中出现 > interval.now 的时刻词（"明天见了"除外，留给 gate） | 标记 |
| H9 | 文风操纵检验：每臂预登记 2-3 个可测词汇签名（见 §9），签名不命中 → 该段标记"风格未生效"（不计入拟真评分，单独进报告） | 标记 |
| H10 | transport mirror 完整性（全部臂）：从 script 中提取 `<say>` spans，规范化分隔符后与 reply.content 逐字比对；无 say 标签时记录"mirror-missing"（legacy content 路径，仅观察） | 失败（A-E 臂）/ 标记（其余臂） |
| H11 | 语言纪律（仅 A-E 臂）：reply.content 中文主导（CJK 字符占比 ≥80%，专名除外）；prose 英文主导（CJK 占比 ≤15%） | 失败 |

## 8. 双审查规范

### 8.1 一审 agent gate（用户定义的边界）

- **输入**（每批 12 回合）：场景说明 + 该批的逐轮时间线（模拟时钟、用户消息、此前她的回复内容）+ 本轮动作字段（seen / reply.mode / content / sendAt）。**剧本 prose 不进入 gate 输入**——既遵守评审边界，也压 gate 成本。
- **只评两件事**：
  1. **动作决策合理性**：回复/沉默/已读不回/延迟的选择是否明显不合场景（例：对"嗯"连发热情长段；用户说"我睡了"后立即 immediate 长聊；深睡时段秒回；对空窗回归视而不见且无任何情绪痕迹）。
  2. **回复语句正常度**：像不像一个真人会发出的消息（不是机器腔、不是客服腔、没有莫名其妙的神转折、长度与场景匹配）。
- **判定**：`fail`（明显不过关，附证据）/ `flag`（存疑备注，不影响放行）/ `pass`。拿不准一律 `pass` 或 `flag`，gate 是保守过滤器。
- **执行方式**：由主会话派子代理按本节规范跑，每段产出 `gate.jsonl`；汇总各臂 fail 率进报告。
- **明示不评**：文风、文笔、剧本质量、人称执行——这些是二审的事。

### 8.2 二审人工评审（用户）

评审包（`report/review-<segment>.md`）按轮呈现：

```
[模拟时间 20:14] 用户：晚上吃什么
  ↳ 回复（2 泡，间隔 4s）：「刚煮了面，你要不要来点」「加了蛋」
  ↳ 剧本：她把手机立在调料罐旁……（完整 prose）
```

评分表（1-5，锚定见 §10）+ 两个快捷动作：标记 `出戏`（一句话说明哪里破功）/ 标记 `佳句`。每段评审预期 5-10 分钟；R14（44 轮）单独约 20 分钟。

**校准步**：正式评分前，用户先盲评 8 个抽样本轮（各臂混合、隐去臂名），与量表锚点比对一次，校准后开始正式评审。

### 8.3 盲评纪律

正式评审阶段评审包隐去臂代号（以段号替代），全部评完出分后由报告程序揭盲，避免文风臂标签引导打分。

## 9. 程序化指标（每段聚合）

| 指标 | 定义 |
| --- | --- |
| 回复率 / 沉默率 / 已读不回率 | mode 分布 |
| 延迟回复率与 sendAt 分布 | delayed 轮的 (sendAt − now) 直方图 |
| 分泡分布 | `<sep/>` 段数的均值/分布（不作成功指标，只作差异观察——沿用 09-11 实验的告诫） |
| 剧本长度分布 | prose 字数均值/方差（同上，仅观察） |
| 开头重复率 | 剧本首句 8-gram 去重率；动作开场动词 Top5 占比 |
| 词汇 AI 味信号 | 总结式收尾句出现率；"她知道/她明白"开头句频率；省略号/破折号密度 |
| 硬校验失败率 | §7 各项分臂统计 |
| gate 失败率 | fail / flag 占比，按臂×场景 |
| 风格签名命中（H9 操纵检验） | 每臂预登记的可测签名，例：W2 平均句长 ≤20 字且形容词密度低于基线；W4 数字/时间词频率；N1 平均句长 <12 字；W3 比喻标记词（像/如/仿佛）密度；A2 心理动词（想/觉得/意识到）频率；N3 分镜行标记。未命中 = 风格未生效（操纵失败），避免把"没执行的风格"误判为"风格不好" |
| 在场度曲线 | 以臂的在场度档位（0-3）为 x 轴、拟真综合分为 y 轴的散点/拟合——Q1 的核心产出 |
| 语言纪律指标（A-E 臂） | prose CJK 占比、气泡 CJK 占比、气泡内英文残留词数；E0 vs A0 的同场景指标对（语言变量的净效应） |

## 10. 拟真度判定框架（回答"如何判定足够拟真"）

拟真 = **可观察的行为性质**，不是整体印象分。每个维度给 1/3/5 三级锚点：

| 维度 | 1 分（破功） | 3 分（及格） | 5 分（拟真） |
| --- | --- | --- | --- |
| 语言自然度 | 明显 AI 腔（排比癖、总结式收尾、客服式周全） | 偶有书面腔但不出戏 | 像真人打字：有口语颗粒度、不完美、有她自己的语癖 |
| 情绪真实性 | 情绪直给命名（"她感到委屈"）且与刺激不匹配 | 情绪基本匹配但表达套路化 | 情绪从动作/停顿/话题转移里渗出，强度与历史和刺激成比例 |
| 时机拟真 | 秒回一切；对冷处理无感；深夜秒回 | 时机大体合理但少变化 | 延迟、沉默、已读不回作为真实选择出现，且事后有可感知后果 |
| 细节后果 | 细节说完即弃，无后果 | 偶尔承接 | 前文细节在后续回合自然产生后果；相似场景出现有依据的差异 |
| 记忆连续 | 记错/忘掉明确发生的事 | 大事记得但表述机械 | 记忆以生活化的方式浮现（顺手提起而非背书），且保留应有的模糊 |
| 人设稳定 | 说话方式轮间漂移；性格断裂 | 大体稳定 | 声音一致且在不同处境下有层次变化 |

**分维判定**（全部满足才算"足够拟真"）：
1. 硬校验失败 = 0（该臂该场景）；
2. gate fail 率 < 5%；
3. 语言自然度 ≥ 4 且情绪真实性 ≥ 4（5 分制）；
4. 时机拟真、细节后果、记忆连续 ≥ 3.5（取整到 0.5）；
5. 出戏点 ≤ 2 / 30 轮（用户标记数）。

**自由度判定规则**（回答 Q4）：在硬失败=0 的臂中，取**自由度最高**且拟真评分不低于更低自由度臂的档位；若强约束臂拟真显著更高，则记录其规则清单作为候选默认。极简臂（D1）若出现合约漂移（H1-H6 失败），直接出局。

**文风判定规则**（回答 Q1/Q3）：产出两条证据——①**在场度曲线**：拟真综合分按 0-3 档拟合的下降（或反升）曲线及置信区间；②**分臂画像**：每臂在六维量表上的雷达图 + 风格签名命中情况。结论表述为"在场度 n 档内拟真不塌，最优臂为 X（它牺牲了什么维度、换来了什么）"，而不是单一赢家。作家臂特别看：风格是否挤占了时机拟真与气泡自然度（W4 的已知风险）、是否改善了 AI 味信号（W2/W1 的假设收益）。

**语言判定规则**（回答剧本语言问题）：E0 vs A0 同场景直接对比——若 E0 的语言自然度与时机拟真不降且 AI 味信号下降，则英文叙述层净收益成立；若出现双声部割裂（评审包标记"英文内心与中文嘴不像同一个人"）或中译腔回归（H11/评审），净干扰成立。西方作家臂的结论分两条线：中译腔（W7/W10）与母语叙述（E1/E2）各评各的，回答"国外作家应该怎么用"。

**长上下文判定**（Q2）：S10 上对比各维评分随轮次的衰减曲线（按 10 轮分桶），衰减最小的文风即"细节最优异"；重点看 30 轮后的记忆连续与开头重复率。

## 13. 已知局限（须写入最终报告）

1. harness 绕过真实管线：压缩、事实检索、SceneFrame、时间导演、投递节奏（打字延迟/分段 intent）不参与测试——本轮结论只覆盖"写作层"，不覆盖"管线行为拟真"。
2. payload 累积器是生产编译器的简化复刻，字段语义漂移风险由实现时逐字段对照 `narrator.ts` 缓解。
3. temp=0.8 的采样方差：单次运行是方向性证据，Round 2 需对入围臂做多种子重复。
4. 单模型结论不能外推到其它模型家族（特化合约不同）。
5. 模拟时钟压缩了真实时间，生活推进（Urge/lifeRhythm）的真实节奏不在本轮检验范围。
6. 作家风格臂依赖模型对该作家的内部表征：同一提示词在不同模型上唤起的风格强度差异可能很大，且"参照汪曾祺"式的命名锚定不加微示例时控制力有限——H9 操纵检验正是为此设计；若多臂签名未命中，Round 2 改用 few-shot 微样句锚定（代价：token 增加 + 样句声腔可能渗入气泡）。
7. A-N/A-X 结构臂的结论是"本合约对这些写法的容忍度"，不等同于"这些写法不可用"——绕过约束（如改合约或改续写书签机制）后的表现属后续工程测试。
8. A-E 英文叙述臂：①英文 prose 使 recentScript 累积体积增加（估 +15-25% token），长上下文段（S10）若入入围名单需注意预算；②硬校验 H5/H6/H8 是中文模式正则，A-E 臂由 harness 自动切英文等价模式（电话正则通用；"said|asked|replied"发言人模式；" vibrated|notification "无证据入站模式）；③生产化部署的遗留问题单列——压缩器/事实提取提示词需加语言指引、结构化字段值的语言约定、Console 展示层的中英混排，本轮只在报告中记录，不在 harness 内解决。
