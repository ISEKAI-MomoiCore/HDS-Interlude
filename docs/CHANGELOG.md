## 1.0.1（2026-11-26，正式版）

- 由 `1.0.1-rc63` 直接晋升；运行行为、默认配置和数据库结构没有变化。rc63 用户升级不需要额外迁移。
- 正式版包含九档 Focus 与事件注意度标注、带涉入标签的世界播种事件、私聊逐泡发送与打断恢复，以及 Koishi 日志和后台任务稳定性修复。具体行为变化保留在下方相应候选版本的记录中。
- npm 包、运行时版本、README、指南与 HTML 配置向导统一使用 `1.0.1`，本地安装包为 `koishi-plugin-hds-interlude-1.0.1.tgz`。

## 1.0.1-rc63（2026-11-26，逐泡恢复、Koishi 日志与后台稳定性）

以下为相对本地 `1.0.1-rc62` 安装包的增量；rc62 已发布包保持原样。

### 私聊逐泡持久化与恢复

- 正式剧本、投递账本和私聊整组待发气泡在同一数据库事务中提交。事务成功后才激活计时器、实时路由与回忆缓存；事务失败不会留下缺少计划的待发账本。
- 取消一位参与者的发送计划后，按原有白名单重新安排故事最早的唤醒，包含其他人已经到期的分段。被打断或正在发送的分段不会挡住另一位参与者的到期分段。
- 恢复扫描对旧版遗留的「有待发账本、无逐泡计划」按动作告警，不让通用补偿绕过逐泡顺序或补发旧稿。已开始发送但结果未知的气泡不盲目重发。

### Koishi 日志与专属 Console

- 区分模型输出校验、剧本提交、回复排程、适配器开始发送和平台确认记账。「待发」「取消」「失败」「结果未知」有独立表述；未写作的手动推进不再报成功，传输超时也不宣称已安排补发。
- 启动、预设同步、Console 资源与 Provider 日志统一遵循 HDSI 日志策略。`silent` 抑制普通 HDSI 日志，盲区健康心跳单独控制；非重载导致的到期唤醒异常按警告报告。
- 新增默认关闭的 `logging.logModelResponse`，在诊断档与 debug 级别同时开启时才预览模型原始响应或拒绝字段。消息和剧本预览仍独立控制；普通 Provider 错误默认不展开响应正文。专属配置中心随服务端 Schema 显示新版日志与浏览参数说明。

### 长时运行稳定性

- 到期网页观察和 QQ 空间动作在故事队列外等待，在队列内短暂准备和提交；失效任务不能把旧观察写回已重置的故事。天气轮询覆盖拉取到提交的整个在途阶段，同一实例不叠加多轮。
- 浏览器总时限覆盖等待槽位、建页、导航、正文提取与关页，图片降采样和抽帧也有独立总时限。Chromium 不响应时不再卡住调用方，也不会反复创建页面占满资源。
- 原生 OneBot QQ 空间动作等待回执最多 30 秒，桌面桥沿用已有超时。到期动作执行前持久化消费意图；回执不明记 `unknown` 并保守计入配额，不自动重试非幂等动作。
- 待发群气泡补偿按群目标恢复，兼容旧 `group:群号` 和注册的群端点，不再因没有私聊参与者而误取消。继续校验群白名单及端点，仅补投合法目标的未确认分段；补偿扫描范围和历史召回策略不变。

### 文档与发布材料

- README、部署/配置/命令指南、当前架构、功能设计、Koishi Console 日志说明和一条龙 HTML 安装向导同步至 rc63。安装包包含重建的服务端、类型声明与 Console 资源。

## 1.0.1-rc62（2026-11-26）

### 私聊逐气泡投递

- 当前私聊的即时文本回复逐泡输出 `bubbleDelaySeconds`，完整校验后再投递。首泡计入已过去的模型耗时，后续泡以平台确认上一泡为计时起点。
- 新私聊打断尚未交给平台的气泡。下一轮按动作获得已确认、已取消和未确认的泡信息，并可按批内序号关联触发消息。
- 专属配置中心更新打字与取消说明。安装向导、配置指南和发布材料同步到 rc62。

### 主叙事提示词边界修正

- 区分平台记录、天气快照与主角亲历：好友动态和评论记录不代表主角已看过或收到设备通知，实况天气不证明开始时间或持续时长。T 档不规定感知顺序，也不要求逐条写入剧本。
- 私聊用「拟稿未发」「当下发送」「计划稍后发送」三个短例，明确即时发送的原话同时出现在剧本和 `reply.content`；`sendAt` 仅用于延时示例。回复输出协议、实际投递和默认写作风格不变。

### Focus、世界事件标签与注意度标注

- `lifeRhythm.attention` 新增九档细分 focus；旧档位继续可读，下游 Urge 和群聊意愿经集中映射兼容。
- 主叙事在正式剧本的 `lifeHandoff.focus` 中引用结尾原句；focus 仅在剧本提交后写入，并以剧本时间和条目 ID 记录证据。
- 压缩器只为最新且缺少主叙事 focus 的正式剧本补写状态，过期结果和旧条目不能覆盖新证据。
- 移除入站私聊续期及 Urge 自主改写 focus；`AgencyWindow.deviceAccess` 保持独立。
- 世界播种器在生成时同时提交 `importance` 和 `involvement`，宿主沿用原有排期并传递标签。实况天气保留原始天气码、风速和采样变化证据，注入条件不变。
- 主叙事在原有材料前添加 T1–T5 注意度标注，不重排、不过滤，不改变固定 system 合约。网页复调和输出恢复沿用同轮 Focus。
- Koishi Console 概览新增「Focus 与事件注意度」只读卡，展示有效性及当前规则预览；世界播种器和实况天气的配置说明同步更新。

## 1.0.1-rc61（2026-11-20，配置保存与关系接线修复 + 主动额度纠正 + 模型响应恢复）

本版本基于 `1.0.1-rc60`，包含当前工作区已完成的 Console、Issue #26/#28 和技术债 X2 / X1 / P2 修复。

### Console 配置与概览

- 配置中心首次打开显示分类总览；选择配置节后按窗口记住位置，保存和插件重载后继续留在当前节。
- “保存本节”接入真实配置更新，返回规范化表单值与密钥占位值；“保存并重载”主动重载插件，避免界面显示已保存而运行配置未更新。
- 故事档案与写作提示词分开展示；主提示词、固定提示词、格式提示词、文风提示词和新故事默认文风集中编辑，保留已有配置键及旧版主提示词兼容。
- 概览补充场景地点、当前活动、叙事焦点、故事时区、剧情时间与补写调度等信息，并调整卡片布局。
- QQ 用户档案改为独立卡片，人物背景与初始关系使用更大的多行编辑区，便于完整修改人设。

### 故事级默认关系（Issue #26）

- 故事设定中的 `defaultRelationship` 接入参与者创建与重置流程，优先级为账号关系 → 参与者预设 → 故事级默认关系 → 全局默认关系。
- 已建立的参与者关系继续保留；完整重置保留故事级默认值，并据此重建关系基线。
- 为该字段补齐类型与配置契约，使 Console 保存值成为人物关系初始化的实际输入。

### 主动联系额度（Issue #28）

- 用户消息回合创建的投递动作携带 `userInitiated` 标记，回复从每目标滚动 24 小时主动额度中排除，避免活跃聊天消耗人物后续主动联系的额度。
- 放行与拦截日志的计数统一采用主动动作口径；最短运行间隔仍参考全部已结算动作。
- 历史无标记记录沿用原计数方式，随滚动窗口自然退出。

### 范围删除与群显著度生命周期（X2 / X1）

- 桌面范围删除由底层清理入口统一排队，修复重复串行排队导致任务等待自身、删除长期无法完成的问题。
- 故事重置、范围删除与清库同步清理对应群显著度；排队瞥视在进入队列及读取故事后复核任务代次，并重新计算当前分数。
- 清理前积累的旧分数和旧任务随生命周期失效，避免已删除内容继续触发人物提前回应。

### 模型响应结束判定与恢复（P2）

- 使用提供商的明确结束信号区分预算截断、未完成流、解析失败、空响应、拒绝、接口错误和超时。可解析 JSON 若被提供商明确标记截断，同样按未完成输出处理。
- OpenAI 兼容与智谱流保留结束原因；无结束信号的 EOF 判为未完成，保留网关返回普通 JSON 的兼容路径。
- 明确预算截断且已配置正输出上限、时间充足时，每服务商每逻辑任务最多追加一次去上限恢复；普通格式错误继续按配置的常规尝试处理。
- Anthropic 保留其必需的输出上限并走常规重试或切换；Gemini 只对明确预算结束原因启用专项恢复。
- 主叙事与 Alter 的同服务商尝试共享时间预算；已早发可见回复后停止整轮重新生成，插件销毁立即终止。失败响应已返回的 usage 继续计入统计，日志补充分类、结束原因、恢复次数与剩余时间。
- 完整输出与可靠的任务生命周期有助于维持剧本连贯、关系基线和人物行动的时间一致性，同时减少无依据重试带来的延迟与消耗。

### 首次部署稳定性

- 修复首次启动的意愿档位迁移过早重载与服务异步注册竞争：迁移在服务就绪后执行，重载后继续提供服务和管理命令。
- 新增真实 Koishi 与内存 SQLite 启动回归，覆盖迁移只提交一次、历史 off+enabled 转为 custom、重载后配置与命令可用。

- 全量测试 1367 项：1363 通过、4 项真实 API 用例跳过、0 失败。

自 rc59-preview.1 起实施、rc60 正式收敛。设计文档：[PROACTIVE_ACTION_UNIFICATION_DESIGN.md](PROACTIVE_ACTION_UNIFICATION_DESIGN.md)。

**核心变更**：
- **统一作者动作**：主叙事以 CONTACT ACTIONS 契约（`<say>` 原文标记 + communicationActions 目标/时机）表达全部出站动作，替代旧意愿数值/容量裁决/联系温度三模式。`future` 进入 contact-plan 人物计划，`fixed-delay` 保持确定延迟。

- **结构化日志**：action-policy/delivery-result/contact-plan 全生命周期事件，持久化后发出、幂等零新增。
- **管理命令**：`interlude.policy`（有效策略/旧链对照）、`interlude.policy.migrate`（旧 proactive-check 迁移）、`interlude.actions`（只读列表）。
