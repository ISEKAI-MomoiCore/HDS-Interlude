### 1.3 1.0.0-beta1 实机观察与路线修正

桌面实例已经证明 M4 的代码链路可运行，但未证明其叙事语义正确。2026-09-04 的连续对话暴露出三项阻断问题：

- `SceneFrame` 把上一段 narrator prose 的尾句写回 `narrativeFocus` 与 `postureOrMotion`，使温水杯、物理讲义、台灯、椅背和打字动作在连续回合中形成自我强化；
- 活跃 Scene 与 DialogueBurst 连续存活约 40 小时，跨越日期与多次活动变化，说明“burst 与 scene 同寿命”和模型自由决定 `scene.close` 均不足以表达真实生活边界；
- 前一日已经存在于原始剧本和长期事实中的事件，因事实候选在语义排序前被截断、原始剧本 embedding 未持久化且活跃场景未关闭，未能进入本轮上下文，模型随后错误否认该事件发生过。

这与 0.1.2 回滚文档记录的失败机制同源：结构化场景开始替代原始剧本的语义和写作纹理，并将自己的概括结果循环喂回下一轮。M4.1 因此不是给现有提示增加反重复补丁，而是恢复以下权威关系：

```text
近期原始剧本 / 命中的历史原文
  > 带来源的事实与 continuity
  > SceneFrame 导航证据
  > 无来源的推断
```

0.1.4 的剧本核心提示词重新作为主提示骨架。`recentScript` 是连续续写的第一上下文；SceneFrame 只为宿主检索、边界判断和原文窗口外的少量事实补位，不能保存 prose 表达，也不能成为“稳定续写点”。在 M4.1 的真实回放、跨日召回和 24/72 小时观察通过前，除不改变输出语义的 M5 提交边界初部署外，M5 完整收束及 M6–M10 冻结。

### 1.4 2026-09-05 M5 补充收束记录

针对实机高密度对话仍反复出现“重建时间地点 → 看见消息 → 评价用户 → 敲字 → 收起手机”的固定形态，本轮只收束主模型协议和宿主提交边界，不改变数据库、投递策略或模型调用次数：

- 已经成立的地点、姿态和设备状态保持隐含，只有实际参与新因果时才重新获得篇幅；高密度对话仍保持相同叙事分辨率，细节转移到新增意义而不是被时间间隔压缩；
- 删除“考虑—草稿—打字—发送”作为每轮默认路线的暗示，可见回复只需成为当前剧本中真实发生的一个行动；

这一阶段不把 `unbound` 升格为重试条件，避免模型为了通过字符串检查形成新的引号模板。只有实机确认模型能稳定把可见原文自然写入剧本后，才考虑在后续提交边界将其变成硬一致性条件。

### 2.1 始终只有一条运行主链

整个改造遵循以下规则：

1. 生产环境中，同一轮只调用一次主模型；
2. 不让 V1 和 V2 同时生成同一轮剧本；
3. 每个里程碑直接替换主链中的一个明确环节；
4. 临时适配器只能单向工作，例如把旧输出转换为新的内部 `ScriptCommitDraft`，不能长期维护两套语义；
5. 版本比较只在离线、冻结输入和数据库副本上顺序回放；
6. 每一步都必须可以通过恢复代码快照和对应数据库备份回退。

### 2.2 每步只改变一个主要变量

禁止在同一个里程碑中同时改动：

- 主提示词的中心写作方式；
- 模型输出协议；
- 数据库表结构；
- 长期学习算法；
- 消息投递语义。

一次只改变其中一个轴，其余部分通过适配器维持原行为。这样才能判断真实感变化来自哪里，也能让每次修正保持 subtle。

### 2.3 正向写作框架优先

文学表现、连续性、节奏和人物感由正向上下文引导；确定性的宿主检测只保留给不能交给文风解决的问题。

| 问题类型 | 首选手段 | 保留硬校验 |
| --- | --- | --- |
| 场景连续性 | 提供近期原始剧本；只在原文窗口不足时补充带来源的当前场景证据 | 拒绝无因果来源的地点、时间跳变 |
| 人物语言 | 提供人物习惯、关系语境和正向声音锚点 | 只校验消息与剧本是否逐字一致 |
| 剧本节奏 | 提供当前叙事焦点和开放动作 | 不再按字数、段数或结尾形式拒绝 |
| 情节自然性 | 提供可继续发展的因果锚点 | 只拒绝越过世界事实的事件 |
| 回复时机 | 在剧本中提供设备、注意力和生活状态 | 只校验不可能的行动能力和时间 |
| 长期发展 | 提供带来源的剧本证据 | 只阻止无证据写入稳定人格 |
| 投递 | 剧本生成完整消息事件 | 严格校验事件身份、原文和投递结果 |

宿主验证器不评价“写得好不好”，也不通过重复重试逼模型写成某种模板。它只守住时间、身份、权限、数据结构和已发生事实。

## 3. 正向提示框架的迁移目标

原提示词中的限制式表达应按下表逐步替换。每次替换后先回放和观察，不一次性重写全部 system prompt。

| 原限制式表达 | 新的正向框架 |
| --- | --- |
| 不要像问答助手一样回复 | 新消息进入主角正在发生的生活；续写它实际造成的感知、动作和语言 |
| 不要重复上一轮结构 | 从上一段尚未完成的动作、情绪和话题自然接续，让形式由当前焦点产生 |
| 每轮写 400–700 字 | 赋予每个新事件稳定而完整的因果与感官重量；篇幅随新增事件自然形成 |
| 不要虚构新事件 | 当前可发展的因果锚点包括这些外部事件、未完成动作、日程边界和环境观察 |
| 不要总以收手机或回到老师结尾 | 在权威现在停止，保留仍在进行的动作、注意力和未说完之处 |
| 不得添加 timelinePlan 外的事件 | 这个时间窗口提供以下可发生的 beat，沿它们渲染连续生活 |
| 避免相同气泡结构 | 在类似生活状态下，她通常在这些表达范围中自然变化 |
| 不要把临时情绪写入人格 | 稳定发展由这些跨场景证据支持；当前情绪继续作为场景状态存在 |

固定提示词最终只描述“这个世界如何继续”，不再像检查清单一样反复告诉模型哪些句子不能写。

## 8. M3：第一轮正向主提示词迁移

这是第一次有意改变写作行为，但只改固定主提示词，不同时修改 payload、输出 schema 或数据库。

### M3.1 先删除三个冲突源

从 `src/narrator.ts::systemPrompt()` 删除：

1. 每个实时回合 400–700 字；
2. 每轮是全新作品而非系列下一段；
3. 通过列举旧开头、旧动作和旧结尾来要求反重复。

不要用另一组禁令替换它们。

### M3.2 加入短小的正向连续剧本核心

建议固定核心不超过约 8–12 条语义规则，中心表达为：

```text
Continue the protagonist's already-running life from the final established
moment to the authoritative present. The incoming message is one new event
inside that life. Let attention, action, feeling and any message grow from the
current scene. Carry unfinished movement and subtext forward. Give every new
event enough concrete detail to remain stable in later scenes. Stop at the
present with whatever is genuinely still in motion.
```

中文含义应保持为：

- 延续已经发生的生活；
- 新消息进入生活，而不是要求回答；
- 从现有动作、注意力、情绪和关系中长出后续；
- 每个新增事件获得足够稳定的具体性；
- 在真实现在停止，并保留自然未完成状态。

### M3.3 不再用格式惩罚文学变化

- 空 script 仍是协议失败；
- 时间越界、消息原文不一致仍是协议失败；
- 字数、段落数、开头形式、结尾动作不再触发重试；
- 重复风格先只记录指标，不向模型注入反向命令。


M4 已建立 `SceneFrame`、`DialogueBurst` 和七段式 context compiler，并验证了来源 ID、共享剧本隐私和 legacy/cache-first 事实等价。这些工程边界继续保留，但 1.0.0-beta1 的实机对话证明其权威关系需要校正。

### M4.1 目标

恢复 0.1.4 已验证的自然语言连续性：主模型首先阅读近期原始剧本和命中的历史原文，再借助少量带来源的事实继续写同一部生活剧本。SceneFrame 是导航证据，不是剧本摘要、写作模板或续写稳定点。

M4.1 必须守住四项不变量：

1. 用户消息仍只是进入当前生活的一项外部事件；
2. 回复必须是同一段剧本因果链中的可见动作；
3. 原始剧本不可由 SceneFrame、事实、logical turn 或摘要替代；
4. 不按消息间隔、消息条数或固定字数改变剧本精细度。

### M4.1-A：冻结实机失败夹具

- 备份 1.0.0-beta1 的源码、发布包、桌面实例配置和数据库；
- 保存“温水杯/物理讲义/台灯”连续复读片段；
- 保存“星期二男孩 13/27”前一日发生、次日错误否认的完整原始条目、事实候选排序和模型 payload；
- 固化 0.1.4 system prompt、recentScript 投影与 12K 原文预算为对照快照；
- 记录同一模型、温度、人物设定和输入序列，后续回放不得改变比较条件。

### M4.1-B：恢复 0.1.4 剧本核心提示词

以 0.1.4 的主提示骨架为准：模型是长期生活剧本的主叙事作者，主角及其正在展开的生活始终是重心，消息只是进入生活的一个事件。

提示词权威顺序调整为：

```text
currentEvent：本轮唯一的新事件
recentScript：紧邻本轮的连续剧本原文，续写第一依据
recalledScript：按当前事件命中的历史原文片段
continuity / facts：原文窗口之外的低频事实辅助
currentSceneEvidence：必要时补位的带来源导航证据
```

删除“`currentSceneFrame` is the stable point of continuation”及把七段式字段描述为同等写作支架的表达。改用短小的正向核心：阅读已经发生的剧本，理解尚未完成的动作、关系温度和潜台词，让当前事件进入其中，并写出同一部剧本的下一段。

增加认知边界：召回内容是人物此刻能够自然想起的相关经历，不是完整档案；没有命中不是“从未发生”的证据。证据不足时，以迟疑、模糊印象或承认暂时想不起来继续剧情。

### M4.1-C：给 recentScript 建立不可绕过的完整性门槛

- 正常已有故事的实时回合必须含非空 `recentScript`；数据库有可见历史而编译结果为空时，本轮作为上下文故障处理，不静默生成；
- 保留条目下限与时间窗口的并集，起始配置维持至少 50 条和至少 12K 原文字符，并离线比较 12K/16K；
- 最近真实收发消息受单独保护，不因较长 narrator prose 被字符预算挤出；
- `recentExchange` 只强调真实收发消息和已投递动作，不复制 narrator prose；
- legacy 与 cache-first 可以改变顺序和标签，但不得改变可见原文、来源、时间和关系隔离语义。

### M4.1-D：把 SceneFrame 降级为 CurrentSceneEvidence

宿主内部可以继续使用 `SceneFrame` 类型和 frameId，但主模型只在原文窗口不足时接收精简的 `currentSceneEvidence`：

```ts
interface CurrentSceneEvidence {
  sceneId?: number
  place?: SourcedValue<string>
  presentPeople: SourcedValue<string>[]
  ongoingActivity?: SourcedValue<string>
  deviceAccess?: SourcedValue<string>
  privacy?: SourcedValue<string>
  attention?: SourcedValue<string>
  openLoops: SourcedValue<string>[]
}
```

不得从 narrator prose 的尾句写入 `narrativeFocus`、`postureOrMotion` 或任何同义字段。环境修辞、偶然道具、句式和收尾动作不属于状态。`workingDetails` 只保留仍未解决、仍与当前生活有关且有来源的具体事项；已解决项显式完成，而不是依靠数组尾部淘汰。

如果 recentScript 已经清楚包含当前地点、活动和姿态，相同证据不重复注入主提示。SceneFrame 主要服务宿主的检索、场景边界与行动能力判断。

### M4.1-E：修复跨日原始剧本召回

召回改为“索引命中，原文回取”：

```text
当前事件
  → 关键词 / 实体 / 日期 / 语义 / 未完成事项候选并集
  → 统一排序
  → 命中 entryId 或 fact.sourceEntryIds
  → 回取命中点前后的连续原始剧本
  → recalledScript
```

- 为 `interlude_script_entry` 注册可空 `embedding` 字段，使用幂等迁移并在后台渐进回填；
- 语义候选不能先被 importance/top-N 截断；高重要度、最近完成、未完成承诺、词法、日期实体与向量候选先取并集；
- 单个命中不只返回 300 字符摘要，应按关系可见性回取相邻条目和必要 narrator prose；
- Embedding 失败时保留词法、实体、时间和来源 entryId 回取；
- 相似 prose 只用于定位事件，不把大量同风格段落反复注入形成文风自模仿。

### M4.1-F：建立事件式 Scene / DialogueBurst 边界

Scene 由已经提交的生活变化结束：睡眠与新一天、明确换地点、主要活动切换、在场结构改变或现实目标转换。时间差只能触发边界检查，不能直接改变叙事精度。

DialogueBurst 表示局部互动因果链，可以在 Scene 不变时因问题落下、话题无因果转换、注意力回到生活或新外部事件打断而更新。它不再与 Scene 同寿命。修复 `entryCount` 每次压缩归零的问题，并让关闭决策携带具体来源事件和原因；压缩模型可以提出证据，宿主状态机负责确认。

## 10. M5：Script-first 提交收束，不让主模型写事件表

### 路线修正

取消原计划“主模型原生返回完整 events、frameChanges 和 developmentEvidence”。该协议会让主模型同时写剧本、拆事件、填因果图和标注学习证据，与 0.1.2 已验证失败的认知过载结构过于接近。

M5 保留 M2 已有的内部 `ScriptCommitDraft`，但明确：模型的第一任务始终是写连续剧本；只有当前 phase 真正需要执行的平台动作才保留最小 transport 字段。事件 ID、来源 ID、commitId 和投递状态由宿主在提交边界生成。

### 主模型最小协议

```json
{
  "script": "同一部生活剧本的连续增量",
  "interaction": {
    "seen": true,
    "reply": {
      "mode": "none|immediate|delayed",
      "content": "必要时的可见消息",
      "sendAt": "仅 delayed 使用"
    }
  }
}
```

群聊、引用、表情、跨关系动作和 intent 仍按实际能力条件注入，不把所有可选 schema 常驻在每一轮提示中。消息文本必须已经自然出现在 `script` 的对应行动里；transport 字段只是宿主执行同一行动所需的句柄，不是第二条叙事链。

### 宿主侧提交

1. 为当前外部事件生成稳定 eventId；
2. 保存完整 script 原文为 commit 的权威文本；
3. 将必要 transport 动作规范化成带 eventId 的内部事件；
4. 验证可见消息与 script 中已经发生的消息一致；
5. 由宿主补充 commitId、frameId、burstId、来源和投递状态；
6. 低频压缩器只在剧本提交之后提取事实索引，不参与本轮写作。

不要用脆弱的全文字符串搜索证明消息存在。应在当前最小协议内保留一个轻量、局部的 script action 标记或由解析器绑定唯一消息段；它只标定 transport 对应位置，不要求模型描述完整事件图。

### 切换方法

- 先固定现有 beta10 输出经 adapter 形成的 `ScriptCommitDraft` 结果；
- 收窄每个 phase 实际注入和接受的字段；
- 把 commit/event 身份生成从 adapter 移到宿主提交边界；
- 确认所有下游只读取规范化 commit 后，删除运行中的 `legacy-adapter`；
- 本阶段不改数据库表、不改投递重试策略、不引入事件学习。

### 正向提示方式

提示模型只完成一件事：让当前事件进入正在发生的生活并写出下一段剧本。必要的可见回复是其中一个动作；主角没有回复时，剧本仍可以完整成立。协议说明与写作提示分区，transport schema 不取得叙事中心。

### 验证

- [x] 主输出没有通用 events、sceneState、sceneTrace、frameChanges 或 developmentEvidence 表；
- [ ] 每条执行中的可见消息在同一 script 中有唯一对应行动和相同文本；当前已建立 `bound | unbound | future` 宿主观测，硬门槛等待实机绑定率；
- [x] 合法沉默不触发缺失回复恢复；
- [x] 任一结构恢复重试都重写完整未提交回合，不单独补造消息；
- [x] 单轮主模型调用数不高于 M4.1；
- [ ] 与 M4.1 相同输入回放时，剧本质量不因协议收束下降；
- [ ] adapter 删除后内部 commit 快照保持等价。

### 暂缓项

实验性“script 完成前先发首泡”继续关闭。只有完整 script 与 transport 行动均已解析、因果位置已绑定后才能投递；流式优化不得先于原子剧本提交恢复。

## 11. M6：建立剧本行动的投递闭环

M6 不改变主模型写作，只把 M5 已规范化的 transport 行动变成可靠、可恢复的宿主事务。权威顺序是：先形成完整 ScriptCommit，再登记投递，再执行平台动作，最后把真实结果写回剧本现实。

### M6.1：使用现有表完成闭环

- 完整 transport action 保存在主 script entry metadata，携带 commitId、eventId 和 script action 位置；
- 拆分气泡、贴图、引用、原生表情和群聊动作只是同一行动的投递 segment；
- `confirmOutgoingDeliveries()` 按 eventId 汇总 `pending | delivered | partial | failed | cancelled`；
- `character-message` 只投影实际成功发送的内容，不成为第二份权威消息；
- 任一失败 segment 都保留明确结果，不能被前一个成功气泡掩盖；
- 下一轮主模型只读取必要的失败/部分投递事实，不读取内部重试状态表。

`1.0.0-beta3-m6` 已完成上述 metadata-only 闭环。当前主提示投影不会序列化内部 `deliveryActions`；已有 system outcome 条目继续以必要现实事实进入既有 recentScript 规则。

### M6.2：Outbox 原位迁移

第一阶段稳定后再新增：

```text
interlude_script_commit
interlude_delivery_outbox
interlude_delivery_outcome
```

迁移顺序：注册新表 → 从现有 metadata 回填 → 离线比较投影视图 → 一次性切换权威写入 → 停止旧写入 → 一个发布周期后删除兼容读取。回填期间不双写，不运行两套发送器。

Outbox 只负责执行已经存在于剧本中的行动，不能在失败重试时重新调用主模型或改写消息内容。

### 验证

- [x] 所有气泡可按同一 eventId 重建为一个完整行动；ChatRhythm 仍读取完整回复，不消费 delivery segment；
- [ ] 崩溃/reload 发送去重待验证：M6.1 未新增发送器，但现有 pending intent 仍有发送成功后、完成记录前的崩溃窗口；
- [x] 账本支持幂等更新；本次源码修正 partial 必须包含实际成功 segment，未确认重试保留 pending；
- [x] 群聊、私聊、贴图、原生表情、引用和跨关系动作沿用同一 commitId/eventId 规则；
- [x] 平台失败只改 metadata outcome 并保留既有失败事实条目，不修改已提交原始剧本；
- [ ] Desktop 实机完成私聊、群聊、贴图、原生表情、引用、跨关系动作与部分失败抽样；

## 12. M7：场景检查点与 EpisodeIndex

### 2026-09-05 本轮源码实施与范围

- M7.3 提前执行：service 不再生成 ChatRhythm prompt，narrator 和 context compiler 均停止投影其 drift 指令。旧统计、配置和函数保留兼容，物理删除留到 M9；这些统计尚不用于人物学习。
- M6→M7 结果反馈：已通过当前关系可见性过滤的 script 条目，其非全部成功行动投影为 `ongoingThreads.deliveryReality`；记录源 entry/event 和必要 segment 内容，不传内部错误原因或重试时间。pending 为未确认，failed 为出错后未确认，平台接受不等于用户已读。跨关系行动再次按关系共享权限过滤。
- M7.1 检查点：只有现有宿主来源校验通过的 scene close 才登记 `sceneCheckpoint`，保存 sceneId、起止时间、首尾 entryId、边界原因和来源 ID，附着在原始边界证据 metadata。读取时可回到原文范围，不新增摘要文本或模型调用。旧场景不补造未经保存的边界证据。
- M7.2 首阶段：历史缓存保留 frameId/checkpoint；对已经过滤可见性的原文构建可丢弃的场景与关系索引。检查点覆盖旧条目，frameId 覆盖新剧本；沿用事实来源、词法、语义候选寻找命中点，再在该索引内回取原文。索引在历史缓存或 audience 发生变化时重建，同版本的可见导航可复用（rc48 工作区 2026-10-11）；每次请求仍单独应用 excludeIds，检查点写入会使历史缓存失效重载。
- 原文截取优先保留真正命中的条目，再选取邻域；每个片段最多 4000 字符、最多三个片段，sourceEntryIds 只声明实际包含的原文。修复旧邻域从头截断可能丢失命中段的问题。

本轮 EpisodeIndex 是场景/关系级导航的首阶段，不宣称已完成实体、物件、承诺、结果等独立语义标签与跨场景事件合并。新检查点只保存边界和原文范围；起终点事实锚点与开放事项仍从原文和现有 facts 回取，尚未新增检查点事实快照。M5 轻量行动引用维持兼容状态，本轮不把 unbound 改成重试条件。

### M7.1：SceneCheckpoint

只有宿主确认结构性场景边界后才生成检查点。检查点保存：

- sceneId、起止 entryId 与本地时间范围；
- 起点和终点的少量事实锚点；
- 已完成动作、仍开放事项和参与关系；
- 相关原始条目 ID；
- 边界类型与边界证据。

检查点摘要用于定位原文，不能直接成为下一轮的写作模板。活跃 Scene 的状态来自近期原文和已确认事件，不从摘要反推 prose。

### M7.2：EpisodeIndex

以事件语义而不是文风相似度建立索引：人物、地点、物件、话题、承诺、结果、日期和关系分支。检索命中 Episode 后回取原始条目邻域；索引只回答“去哪一段找”，不回答“当时具体怎么发生”。

EpisodeIndex 必须可从 `interlude_script_entry` 和来源 ID 全量重建。摘要、embedding 或标签出错时，删除索引重建即可，原始历史保持不变。

### M7.3：逐步停用 ChatRhythm 的负向注入

- 先保留统计和日志，但停止向主提示发送“这轮必须改变气泡数/长度”的反向命令；
- 统计单位改为 M6 的完整 transport 行动，不按 segment 重复计算；
- 删除 sticky exhausted、强制轮换和基于尾部重复次数的写作指令；
- 若保留习惯投影，只能来自跨 Scene 的稳定观察，并用一两句正向概率表达；
- 未证明正向习惯投影优于无投影前，不建立新的 DialogueHabitProfile 数据表。

### 验证

- [ ] 所有 SceneCheckpoint 和 Episode 均能回溯到连续原始 entryId；
- [ ] 删除索引后可以从原始剧本重建等价的检索入口；
- [ ] 同一高密度 burst 不被拆成多个虚假 Episode；
- [ ] Episode 命中后注入的是相关原文邻域，而不是只有摘要；
- [ ] Scene 摘要措辞不会连续复制进下一轮 prose；
- [ ] 停止 ChatRhythm 注入后，结构解析率和平台投递不受影响；
- [ ] 对话气泡变化来自人物与场景，而不是宿主强制轮换。

## 13. M8：收敛时间、记忆与人物学习

M8 只消费已经稳定的原始剧本、EpisodeIndex 和投递结果。它不再改变实时主提示的中心结构。

### M8.1：时间导演瘦身

- 实时用户消息继续不调用时间导演；
- conversation follow-up 和短 due 窗口直接从 recentScript 的未完成动作续写；
- 只有跨越较长后台空档且 Schedule/intent 不能提供足够结构时才生成 BeatSkeleton；
- BeatSkeleton 是已经校验的时间窗口内可发生结构，不规定 prose 篇幅和事件密度；
- 时间模型失败时缩短窗口或等待下次推进，不用自由 prose 猜测大段时间；
- 宿主继续权威处理绝对时间、用户明确报告时间、日程边界和已完成 timeline ledger。

### M8.2：记忆层生产者—消费者审计

| 层 | M8 处理 |
| --- | --- |
| recentScript | 永久保留为连续剧本原文和第一续写上下文 |
| recalledScript | 由 Episode/fact/词法/语义命中后回取的历史原文 |
| SceneFrame | 宿主内部当前证据索引；仅在原文窗口不足时精简投影 |
| facts | 带 sourceEntryIds 的长期检索索引，不直接代替发生过程 |
| continuitySnapshot | 只保存原文窗口外仍影响现在的低频连续性 |
| workingDetails | 并入带生命周期的 open loops；已解决项显式结束 |
| memory 表 | 无独立生产者或消费者时停止写入、验证后删除 |
| delivery summaries | 由 ScriptCommit 与 delivery outcome 确定性投影 |
| timelineCarry | 只保存宿主已确认但尚未完成的 beat，不保存 prose 尾句 |

每次只处理一层：先观测真实消费，再停止写入，再比较关闭读取前后的召回率，最后删除。原始剧本层永不参与此类删除。

### M8.3：人物发展与对话习惯

人物学习从 SceneCheckpoint 的原始证据中低频产生，不在主模型实时输出中索取 `developmentEvidence`：

1. 定义少量受控 dimension 和 global/relationship scope；
2. 压缩任务按 sourceEntryIds 提出候选证据；
3. 一个观察周期只记录、不应用；
4. 同一 burst 和同一 Scene 的重复表现合并为一次贡献；
5. 只有跨 Scene 重复证据或明确重大事件才晋升；
6. 反证降低置信度，当前情绪只留在当前剧本；
7. 停止新的自由路径 statePatch，旧 patch 可映射则迁移，否则归档。

投影给主模型的只能是一两句自然、正向、概率式倾向，且仅在当前事件相关时出现。它不能规定本轮气泡数、句长、标点或强制制造变化。

### 验证

- [ ] payload 每一层有明确生产者、消费者、来源和生命周期；
- [ ] 删除冗余层后原文注入率与历史事件召回率不下降；
- [ ] 相似 prose 不会因向量召回持续自我强化；
- [ ] 相同消息重复十次不会产生十倍人格权重；
- [ ] 所有稳定发展均能回溯到跨 Scene 原始剧本；
- [ ] 关系限定习惯不污染全局人物模型；
- [ ] 连续运行数日后人物变化缓慢可见，无长期零变化或单次突变；
- [ ] 时间导演调用减少后，长空档时间正确率不下降。

### 15.5 发布决策

M10 不是开发结束后的形式检查，而是每个候选版本能否继续推进的发布门。以下任一情况出现即停止升级：

- 原始剧本在有历史的正常实时回合中缺席；
- 辅助结构覆盖原文或把 prose 措辞循环回注；
- 前一日明确事件存在但多通道召回无法触达；

- 主模型为了填写结构化副产物而明显降低剧本质量；
- 原有平台能力、投递幂等或数据库恢复出现退化。

通过 M10 后才允许把当前路线称为 V2 稳定架构；版本号是否进入 RC 由真实运行和盲评结果决定，不由里程碑编号自动决定。

## 16. 拟真度验证表

拟真度必须评价整段剧本，不能只截取角色回复。

### 16.1 连续生活

- [ ] 用户不发消息时，主角仍有自己的活动和未完成动作；
- [ ] 用户消息进入已有生活，而不是让世界重新围绕问题开场；
- [ ] 高频对话不反复重设地点、姿态和情绪；
- [ ] 短窗口没有降低事件语义精度；
- [ ] 长窗口没有凭空填满琐碎事件；
- [ ] 场景结束来自生活变化，而不是每轮固定收束。

### 16.2 剧本与消息耦合

- [ ] 每条消息都能在同一 ScriptCommit 中找到感知、动作或情绪因果；
- [ ] 可见消息不是对用户文本的通用问答改写；
- [ ] 单独删除消息事件后，剧本因果会出现真实缺口；
- [ ] 沉默在剧本中成立，而不是因为字段缺失；
- [ ] 回复后的生活延续与消息内容相互影响；
- [ ] 平台失败会成为后续世界事实。

### 16.3 高密度稳定性

- [ ] 同一语义拆成 1、5、10 条消息时，人物核心态度基本一致；
- [ ] 消息越密集不会自动产生越多新情节；
- [ ] 语言不会因窗口缩短而突然变得概括、模板化或失去人物声音；
- [ ] 原有场景事实不会在逐轮复述中漂移；
- [ ] 同一 burst 只对长期学习贡献一次场景权重；
- [ ] 人格变化幅度不与消息条数成比例。

### 16.4 人物发展

- [ ] 人物变化缓慢但能观察到；
- [ ] 每项稳定变化有跨场景或重大事件证据；
- [ ] 即时情绪不会晋升成永久性格；
- [ ] 面对不同参与者的关系习惯保持隔离；
- [ ] 对话习惯表现为自然范围，不表现为系统强制轮换；
- [ ] 反证能够降低旧结论而非继续叠加。

### 16.5 正向框架质量

- [ ] 主提示词主要描述“如何继续生活”，而不是罗列禁止事项；
- [ ] 风格提示以正向声音、焦点和动作惯性为主；
- [ ] 不使用固定字数、固定气泡数和固定结尾作为拟真手段；
- [ ] 写作失败不会触发越来越长的反例清单；
- [ ] 宿主重试只针对结构或现实性错误；
- [ ] 模型能在没有惩罚式 ChatRhythm 的情况下产生条件化变化。
