# 分层彩色日志实现

适用版本：`1.0.1`

## 目标

日志区分收到事件、模型输出校验、剧本提交、发送排程、适配器开始发送和账本状态变更。摘要用于关键结果；标准追加模型和后台任务；诊断追加队列、游标、计时器和 SQLite 临时重试等，其中 debug 记录还要放开级别。非预期的唤醒失败是可见警告，不当作普通计时器噪声。

## 格式

`logging.format` 支持：

- `layered`：默认。阶段主行配合 `├─ / └─` 字段树。
- `compact`：兼容脚本解析的单行文本。
- `detailed`：兼容旧配置的分行文本。

`colors=true` 使用 ANSI 语义色，`colorTheme` 提供两套高对比 256 色调色板：

- `dark`：柔亮青蓝、薄荷绿、粉紫、暖金和珊瑚红，避免深色背景上的灰暗色。
- `light`：深蓝、墨绿、深紫、赭金和暗红，避免白色背景上的浅色发虚。

日志由服务端生成，无法读取 Koishi Console 的 CSS 主题，因此必须在 Console 手动选择。`kaomoji=false` 时改用简洁符号。

## 实现边界

`src/logging.ts` 负责格式化、动作识别、字段拆分和颜色。业务层仍决定哪些事件属于 summary、standard 或 diagnostic。启动、Console 资源、预设和运行中的 Provider 日志走同一个 HDSI 策略；普通日志不输出错误堆栈，结构化 Provider 的响应错误默认不展开响应正文。`logging.level=silent` 抑制普通 HDSI 日志，不影响其他插件或盲区健康心跳。

`blindMode.enabled=true` 时，HDSI 不使用上述业务时间线：普通运行、错误详情、预览与模型侧调试都会静默，仅由服务层按配置间隔输出不含故事内容的健康心跳。失明模式不会改写其它 Koishi 插件的日志策略。

消息预览、剧本预览及模型响应预览分别由 `logMessageContent`、`logScriptPreview` 和 `logModelResponse` 控制，默认均关闭。模型响应预览还要求诊断档与 debug 级别。平台确认只是适配器投递结果，不是已读；超时日志不宣称安排了补发。

## 测试

`test/logging.test.ts` 固定验证用户消息、模型开始、Alter 触发、错误、ANSI 颜色和简洁符号，防止后续改动重新退化成字段堆叠。
