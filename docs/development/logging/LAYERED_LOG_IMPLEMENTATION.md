# 分层彩色日志实现

适用版本：`1.0.1-rc52`

## 目标

标准日志围绕用户能理解的任务时间线组织：收到事件、模型处理、完成、投递。故事 ID、队列、游标、周期扫描、计时器和 SQLite 临时重试只在 diagnostic 模式出现。

## 格式

`logging.format` 支持：

- `layered`：默认。阶段主行配合 `├─ / └─` 字段树。
- `compact`：兼容脚本解析的单行文本。
- `detailed`：兼容旧配置的分行文本。

`colors=true` 使用 ANSI 语义色，`colorTheme` 提供两套高对比 256 色调色板：

- `dark`：柔亮青蓝、薄荷绿、粉紫、暖金和珊瑚红，避免深色背景上的灰暗色。
- `light`：深蓝、墨绿、深紫、赭金和暗红，避免白色背景上的浅色发虚。

日志由服务端生成，无法读取 Koishi Console 的 CSS 主题，因此必须在 Console 手动选择。`kaomoji=false` 时改用简洁符号。

## 实现边界

`src/logging.ts` 负责格式化、动作识别、字段拆分和颜色。业务层仍决定哪些事件属于 summary、standard 或 diagnostic。所有 `Error` 参数只输出 message，不在标准日志展开堆栈；底层 Provider 的重复警告已降为 debug，最终错误由业务时间线统一报告。

`blindMode.enabled=true` 时，HDSI 不使用上述业务时间线：普通运行、错误详情、预览与模型侧调试都会静默，仅由服务层按配置间隔输出不含故事内容的健康心跳。失明模式不会改写其它 Koishi 插件的日志策略。

## 测试

`test/logging.test.ts` 固定验证用户消息、模型开始、Alter 触发、错误、ANSI 颜色和简洁符号，防止后续改动重新退化成字段堆叠。
