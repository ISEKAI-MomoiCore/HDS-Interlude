## P2：响应事实与恢复

新增 provider-response.ts，为预算截断、解析失败、空响应、未完成流、拒绝、提供商错误和超时提供结构化分类。

- 主叙事与侧任务从响应结束原因识别预算截断；诊断原文不再决定恢复资格。
- 非流式和通用/智谱 SSE 保留 finish reason；明确截断在解析前拒绝，即使文本能解析成 JSON。
- 正常结束原因或流终止标记提供完成依据；无完成依据的 EOF 作为未完成流处理。
- 通用 SSE 保留普通 JSON 降级路径。Anthropic 的已知预算截断接入分类，保留必需输出上限并走普通重试/切换。
- Gemini 仅明确预算原因的 incomplete 可触发专用恢复，未知原因保留未完成语义。
- 已配置正输出上限、预算截断明确且时间充足时，同服务商在一次逻辑任务中最多增加一次去上限恢复。
- 主叙事和 Alter 的普通尝试与恢复共享单服务商总时间预算，其余侧任务在本次调用中共享预算。
- 插件销毁立即退出；早发可见回复后停止整轮重新生成。
- 保留已返回的失败响应 usage；SSE 在 finally 中结算每次请求，再使用既有聚合逻辑。

### 可见行为变化

1. 无效 JSON、空响应与 HTTP 错误不会再仅凭文案获得一次额外的去上限重试，继续使用配置的普通尝试。
2. 缺少 finish reason 的正常非流式响应保持兼容。
3. 缺少终止信号的 SSE 即使已有文本，也以未完成处理。
4. 主叙事的 timeout 是同服务商本轮所有尝试共享的时间预算。智谱主叙事同样受该总时限约束，仍保留首可见 token 与流内静默守卫。
5. 日志新增失败分类、结束原因、恢复次数和剩余时间。
