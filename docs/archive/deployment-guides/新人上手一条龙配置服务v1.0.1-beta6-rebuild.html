概览：你要搭起什么？

整个流程大约 20–40 分钟。每一步都有可直接复制的命令，跟着做即可。

大模型 API支持的官方预设或 OpenAI 兼容接口

HDSI（HDS Interlude）让机器人扮演一个"有自己生活"的角色：它会决定何时看到消息、立即回复、延迟回复还是沉默，并在无对话时继续推进自己的日常。

开始前请准备好

  • 一台能长期开机的 Windows 电脑（普通家用配置即可）
  • 一个用作机器人的 QQ 账号（建议单独注册小号）
  • 一个大模型 API Key——支持智谱、OpenAI、DeepSeek、Kimi、阿里百炼、硅基流动、OpenRouter、Gemini，或 OpenAI 兼容接口
  • 你的个人 QQ 号（用来和角色聊天测试）
⚠ 机器人账号建议使用小号。协议桥接属于第三方实现，理论上存在账号风险，请勿使用存有重要资料的主号。

10 个操作步骤 + 1 页概览

  1. 安装 Node.js（一切的地基）
  2. 安装 SnowLuma（把 QQ 变成机器人接口）
  3. 配置 SnowLuma（界面里直接注入 QQ 进程 + 建立通信通道）
  4. 安装 Koishi（npm 官方脚手架，一条命令）
  5. 安装插件（命令行 npm，或直接在插件市场下载）
  6. 填写连接参数（机器人 QQ、端口、Token）
  7. 配置模型中心（多供应商、多模型协作）
  8. 填写角色设定（人设 + 白名单）
  9. 世界与发言设定（世界预设 + 发言节奏）
  10. 生成 koishi.yml 并启动，开始第一句对话

本向导面向全新 Koishi 项目，生成的配置会覆盖脚手架默认 koishi.yml。左侧边栏可以随时跳转；你填写的内容会自动保存在浏览器里。

第 1 步 · 安装 Node.js

Koishi 和 HDSI 都跑在 Node.js 上。推荐安装 22.x LTS 版本。

方式 A：命令行安装 推荐 · 需 Win10+

按 Win 键，输入 powershell，以普通身份打开 PowerShell，粘贴运行：

winget install -e --id OpenJS.NodeJS.LTS

装完后关闭并重新打开 PowerShell 窗口（让环境变量生效）。

方式 B：官网安装包

打开 nodejs.org/zh-cn，下载 LTS 长期支持版（≥ 22.x），双击安装，一路"下一步"即可，全部选项保持默认。

验证安装

重新打开一个 PowerShell，运行：

node -v ; npm -v

看到两个版本号（例如 v22.x.x 和 10.x.x）就说明成功了。

💡 如果提示"无法将 node 识别为 cmdlet"，说明环境变量没生效——重启一下电脑再试。

第 2 步 · 安装 SnowLuma

SnowLuma 把电脑 QQ 的会话桥接成标准 OneBot 协议，是 Koishi 和 QQ 之间的翻译官。

前置：安装电脑 QQ

如果还没装，去 im.qq.com/pc 下载最新版 QQ（NT 内核）并安装。安装好即可，下一步 SnowLuma 会直接注入它的进程。

下载 SnowLuma

  1. 打开 github.com/SnowLuma/SnowLuma/releases
  2. 在最新版本的 Assets 里，选择 Windows 完整发行包（文件名通常含 win 和 full；完整包自带运行环境，不需要再装别的）
  3. 下载后解压到一个不含中文和空格的路径，例如 C:\SnowLuma
💡 GitHub 访问慢的话，可以多刷新几次，或使用镜像加速工具下载。

启动

双击解压目录里的 launcher.bat。首次启动会初始化，看到日志滚动即成功。

启动日志里会出现 WebUI 初始密码，把它记下来（也可以直接复制窗口里的文字）。

⚠ 每次使用机器人都需要保持 SnowLuma 在后台运行。不要关闭 launcher 窗口。

第 3 步 · 配置 SnowLuma

注入 QQ 进程，并建立一条给 Koishi 用的 WebSocket 通道。

① 登录 WebUI

浏览器打开 http://localhost:5099，用启动日志里的初始密码登录。首次进入会有引导向导，按提示完成（同意协议等）。

② 注入 QQ 进程

在 WebUI 中进入「进程注入」页面，选择 QQ 进程并点击注入。SnowLuma 会直接接管 QQ 会话并开始监听登录状态——无需在 SnowLuma 里再次扫码或输入密码，QQ 客户端里正常登录的机器人账号会自动接入。

此后每次开机使用流程：启动 QQ → 启动 SnowLuma（launcher.bat）→ 启动 Koishi。

③ 生成你的连接参数

下面两个值将用于 SnowLuma 和 Koishi 的对接，两边必须完全一致。点"随机生成"可获得一个安全的 Token：

SnowLuma 将监听的本地端口，保持默认 3001 即可（除非被占用）
一串随机密码，防止本机其他程序误连；两边填同一个

④ 新建 WS 服务端节点

注入完成后，点击 WebUI 左侧导航的「节点配置」，选择「WS 服务端」类型新建节点，会弹出「编辑 WebSocket 服务」窗口（本地监听 WebSocket 端口，客户端建立持久连接）。按下表逐项填写：

编辑 WebSocket 服务
启用开启
名称ws-default（默认即可）
主机127.0.0.1
端口3001（上面生成的端口）
路径/（默认即可）
授权 Token上面生成的 Token
消息格式数组（标准 OneBot 段）
角色Universal（收发合一）
上报自身消息关闭

填完点「保存修改」，SnowLuma 就会开始监听这个端口。

💡 Token 两边要一致：既可以把你在这里生成的 Token 粘贴进 SnowLuma，也可以直接用 SnowLuma 授权 Token 一栏自带的「重新生成」+「复制」按钮，把生成的值粘贴回本页第 ③ 步的 Token 输入框——效果一样。
为什么要用 WebSocket 服务器模式？

Koishi 的 OneBot 适配器将作为客户端主动连过来（协议选 ws），这是最简单稳定的连接方式：SnowLuma 当服务器等在那儿，Koishi 启动时自动接入，断线自动重连。

第 4 步 · 安装 Koishi

Koishi 是机器人框架本体，HDSI 是它的一个插件。官方脚手架一条命令搞定。

创建 Koishi 项目

打开 PowerShell，进入你想安装的目录（示例用 C:\），运行官方脚手架：

cd C:\
npm create koishi@latest

脚手架会提问几个问题，推荐这样选：

  • 项目目录名：填一个英文名，例如 hds-bot（路径避免中文和空格）
  • 其余选项直接回车用默认值即可

完成后进入目录并安装依赖：

cd C:\hds-bot
npm install
💡 脚手架通常会自动执行依赖安装，第二条命令跑一下确认没漏即可，很快。

先启动一次看看

npm run start

看到 Koishi 欢迎信息和日志滚动即成功。浏览器打开 http://localhost:5140 能看到控制台界面。

确认正常后在 PowerShell 里按 Ctrl + C 停掉，继续下一步装插件（现在还没装插件，先不用保持运行）。

⚠ 如果端口 5140 被占用报错，先关掉电脑上其他 Koishi / Node 服务再试。

    第 7 步 · 模型中心
    
  
    一行模型连接就是一个实际可调用的模型；勾选它承担什么用途。可以添加多条，让不同任务用不同的模型协作。
    

  
    
    
    五个用途分别用什么模型
    
    
    
      
    用途模型要求推荐
    
      
    主叙事能力要强，决定剧本质量；最好支持 JSON 输出（json-object），不支持时选 prompt-only 也能跑，解析成功率略降gemini-3-flash（多模态强，可顺带看图）、GLM-5.3、DeepSeek-chat、Kimi K2.5、GPT-5-mini
    
      
    后台压缩纯文本输出即可（prompt-only 也行），低频调用，越便宜越好GLM-5.3-Flash、硅基流动 Qwen3-8B（有免费额度）
    
      
    Alter 分析纯文本输出即可；只在情绪累计触发时调用一次，低频同上，用便宜模型
    
      
    Embedding必须支持 /embeddings 接口，普通聊天模型不能勾text-embedding-3-small 等向量模型
    
      
    表情包描述必须能识图的视觉模型各家多模态模型
    
      
    侧端识图主叙事是纯文本模型时，用视觉模型把当前图片转成临时观察Gemini、Qwen-VL、GLM-V 等视觉模型
    
    
    
    
    💡 一条勾选“主叙事”的模型即可开始；建议再配置后台压缩。Alter、Embedding 和表情包都可以以后按需开启。Embedding 只能单独占一条连接，勾选后其它用途会自动取消。
    
  
    

  
    
    
    模型连接列表
    
    
    HDSI 的模型行既是连接配置，也是用途分配中心：主叙事、后台压缩、Alter 情绪分析、Embedding 检索、表情包描述都由各行勾选决定，无需填写任何 providerId / modelId。
    
    
    
    
    
    
    💡 典型用法：第一条用能力强的模型勾选"主叙事"；再添加一条便宜模型只勾"后台压缩 + Alter 分析"，省钱又不影响写作质量。勾选多条主叙事时，failover 会在失败时自动切换。
    
  
    

  
    
    
    图片理解（可选）
    
    
    
    
      
    
      
    
    
    
    
    主叙事模型支持视觉时选 native；纯文本主模型选 sidecar，并在下方模型用途中勾选一条“侧端识图”视觉模型。图片与识别结果都不会写入记忆。

    仅私聊、仅 json-object。未知中转站请先关闭；开启后可更早投递首条回复，但流式收尾失败时不会自动重发可见消息。

          • 机器人不回消息 → 依次确认：机器人 QQ 在 botAccounts、你的 QQ 在 userAccounts、模型 Key 有效、日志里模型调用成功
            • 
      
          • 模型报 429 / 超时 → 免费额度用尽或网络问题；换模型或稍后重试
            • 
      
          • 指令没反应 → 确认消息是私聊发送的，且 Koishi 日志里没有加载失败的插件
            • 
    
          
    
          更详细的排障见 HDSI 的 DEPLOYMENT_GUIDE.md 第八节和 BEGINNER_GUIDE.md。
