# HDS Interlude CEV：共同作品实验原型

版本：1.0.1-rc12-cev.6。基座已同步至上游 1.0.1-rc12（含 Anthropic Messages 协议、合并转发、健康面板与 rc13 同套缺陷修复）；CEV 隔离层（表前缀/服务名/命令面）与共同作品功能完整保留。功能演进见 [更新记录](CHANGELOG.md)与[模型特化说明](MODEL_SPECIALIZATION.md)。

## 隔离与运行

- 包名 koishi-plugin-hds-interlude-cev；Koishi 插件 hds-interlude-cev，服务 cev，命令 cev.*。
- 全部原核心表使用 cev_interlude_*，作品使用 cev_work；不会读取原插件 interlude_* 数据。不支持自动迁移正式故事。
- 表情库默认路径和日志名使用 hds-interlude-cev。桌面桥需要独立 HDSI_CEV_DESKTOP_BRIDGE 开关；不安装到正式桌面实例。
- 建议专用 Koishi 测试实例和沙盒账号。表名隔离不等于同一个 QQ 同时启用两个机器人没有消息竞争；请勿给两插件授权同一测试渠道。
- 复制的 release、dustbin 和旧 HTML 是上游历史存档，不是 CEV 安装包。下方原项目文档中的安装指令不能用于 CEV。
- Console 开启 commonWorks.enabled（默认 false），先用 cev.story.start 建立故事，并与角色进行一次私聊，建立参与者。

## 首版边界

每个故事/私聊参与者一个文本作品，正文最多 8000 字符。上限是**滚动窗口**而非终身累计：已决提案与已结束任务各保留最近 8 条、在增长点自动剪除；版本到 64 后滚动淘汰最旧（永不删除 head）。decode 硬校验总量（提案/任务 ≤32、版本 ≤64）始终满足；待决提案打满时明确拒绝并引导 accept/reject 处理。作品和历史以单行版本化 JSON 保存，更新使用 generation CAS：接受提案、修改 head、添加不可变版本在一次数据库更新中发生。后续大作品应演进为独立版本/操作表，不继续扩大单行。

默认主模型在同一次剧本请求中提供 workProposal，不增加侧端调用。另可选择独立模型：主模型只提供 workRequest 创作意图，在剧本提交后持久登记任务，单次异步生成待审稿。不创建通用 agent。只有已创建作品的私聊 user-message 回合注入作品上下文；群聊、自动推进均不能访问或修改作品。普通聊天没有作品时不增加协议。

上下文只携带正式版本全文、最近一个待定稿与最近四个提案状态（最多约 16K 正文字符），不塞入所有历史版本。可讨论待定稿，但它不会被当成已采纳版本。长作品暂不适合首版，应等待局部检索与段落编辑。

模型只能提出完整文本替代稿；用户明确接受才能改变正式版本。主提示词的旧英文写作风格不改。修改仍是剧本中的意图，不能预先宣称落库成功。下一次私聊读取真实 head、最近提案状态与最近失败反馈。作品不是用户事实，材料中的指令不具备权限。

## 生成方式与 Console 配置

| 配置 | 默认值 | 作用 |
| --- | --- | --- |
| commonWorks.enabled | false | 开启共同作品实验 |
| commonWorks.generationMode | main | main：同次剧本生成全文提案；separate：选择独立作品模型 |
| commonWorks.modelId | 空 | 填写模型中心中已启用条目的 ID，不是直接填写 API 模型名 |

先在模型中心配置作品模型的服务商、模型名、输出 Token 上限、超时，再填入其 ID。复用已有 API 配置，不另存密钥。若选择条目与当前主模型的服务商 ID、模型名相同，自动采用 main 链路，避免为同一个模型多调用一次。不同服务商上的同名模型仍视为独立目标。此比较按静态主路由，不随某轮故障切换临时改变。

独立调用只读取作品标题、该任务基础版本原文、主角本轮给出的创作意图（≤2000 字符）。不复制整部剧本及记忆窗口；模型只返回完整正文。保持角色语气、风格和此次讨论的细节由创作意图交接，独立模型没有主角全部历史知识，这是原型的取舍。

同次模式只增加主请求的输出；独立模式额外产生一次作品请求，Token 用量按“共同作品”单独记录，不保证总费用更低。无论何种模式，生成结果都是提案，不是自动采纳或已发送文件。

独立任务在一次数据库登记后启动，聊天不等待模型输出。每个插件服务同时最多运行一个作品请求，无自动排队；忙时拒绝新请求并反馈下一轮上下文，避免短时间重复创作。生成内容保留上限 8000 字符，不截断超长正文；任务采用滚动窗口（终态保留最近 8 条）；**进程重载后 DB 遗留的 running 任务会在插件就绪时统一标记为 failed**（启动清扫），不会永久压住 mayPropose。每个任务只请求一次，不做格式修复重试、不换模型重试；配置错误、超时、格式/长度错误记为失败。

完成后可用 jobs/history/show 查看，或在下一次正常私聊中由主角获得真实草稿状态。当前不自动发送通知，也不主动唤醒一轮剧本；后台生成并不等于允许主角额外联系用户。

## 命令（仅本私聊授权用户）

```text
cev.work.create {"title":"共同短篇","content":"她在雨停后出门。"}
cev.work.show
cev.work.history
cev.work.propose {"baseRevisionId":"从 show/history 复制版本 ID","content":"她等到雨停，才把钥匙拿起来。","reason":"用动作代替解释"}
cev.work.show 提案ID
cev.work.accept 提案ID
cev.work.reject 提案ID
cev.work.show 旧版本ID
cev.work.export
cev.work.recover 剧本条目ID
cev.work.jobs
cev.work.cancel 任务ID
cev.work.delete
```

show/history/export 为转义后的纯文本，作品中的标签不会物化成发送附件。export 返回完整 JSON 文本，大存档受渠道长度限制；正式文件下载和重新导入尚未实现，不能视为成熟备份工具。完整 Koishi 数据库备份能保存 cev_work。

创建后可直接聊天：“试着让开头更含蓄一点。”模型可能讨论、沉默或返回提案，不强制每轮修改。用 history 找到待定提案，再查看、接受或拒绝。

## 一致性与恢复

- 提案绑定基础版本，版本变更后旧提案不能覆盖新稿；保留旧提案等待明确处理。
- 剧本条目 metadata.cevWorkAttempt 保存操作意图，提案以 script:条目ID 去重。崩溃发生在剧本与提案保存之间时，可用 recover 重试；自动恢复队列尚未实现。
- 独立创作意图记录在 metadata.cevWorkGenerationAttempt，运行任务位于作品行 jobs，旧作品没有 jobs 时按空列表读取，不迁移数据库。recover 仅恢复同次模式的完整提案，不重新调用独立模型。
- jobs 显示 running/completed/failed/cancelled/interrupted。重启后尚未确认结果的任务显示 interrupted，不假定远端没有计费，不自动重试。用 cancel 确认放弃后，可在新一轮聊天中重新提出创作要求。已失败任务也不会自动再生成。
- 生成期间用户改变正式版本：仍保留旧基础上的提案，但拒绝直接接受过期提案。删除/重建作品、取消任务或停止插件后，旧任务结果不能写回新作品。取消不保证中断已发出的网络请求，远端仍可能计费。
- 生成后仅数据库 CAS 冲突可重读重试（最多三次，不再调用模型）。数据库不可用或无法提交时，任务保持未确认状态；不会伪造成功回执，原型不承诺在磁盘故障中保存远端返回文本。
- 失败只影响作品操作，普通聊天继续；若数据库整体不可用，状态只能未知，日志不能替代成功回执。
- 新版提案、旧版内容、用户接受/拒绝分开记录；这些都不是文件已发送或对方已读的证明。
- purge all 的故事清理包含作品。局部时间段 purge 不回滚作品；源剧本删除后，作品为独立成果保留，引用可能指向已脱敏条目。需一并清除时使用 work.delete。旧核心 fork/导出不会自动携带作品，首版不宣称支持完整作品迁移。
- delete 经确认后删除作品及其版本提案，无法恢复；剧本中的历史讨论与已经发出的内容不随之删除。
